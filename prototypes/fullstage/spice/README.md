# ngspice reference: one 12AX7 common-cathode stage

This is the offline "ground truth" the DK (and later WDF) models are tested against. It proves our
maths matches the *circuit*; it is only as true to a real valve as the Koren model is.

**Component values are example values, not Culture Vulture values.** HT 300 V, Ra 100k, Rk 1.5k and
Rg 1M are from Merlin Blencowe, *Designing Valve Preamps for Guitar and Bass*, ch. 1
(https://www.valvewizard.co.uk/Common_Gain_Stage.pdf). Cin 22n, Ck 22u, Cout 22n, Rl 1M, Rs 1k and the
68k grid stopper are round values chosen by us. The values live in `dk/circuit.VALUES`; see its docstring.

## Setup
```bash
# ngspice 41 from conda-forge, in a local micromamba env (what we used)
micromamba create -y -p ../.ngenv -c conda-forge ngspice=41
bash models/fetch_models.sh     # Koren 12AX7 model, hash-checked (not redistributed, git-ignored)
```
`.spiceinit` sets `ngbehavior=psa` (PSpice compatibility, needed for the Koren B-source syntax).
`out/` is git-ignored (the transient dumps are several MB each).

## Netlists are generated (#4)
Every netlist is generated by `run_refs.netlist(model, analysis)` from one source of truth:

| what | where |
|---|---|
| component values (HT, Rs, Cin, Rg, Rgs, Ra, Rk, Ck, Cout, Rl; valve caps CCG/CGP/CCP) | `dk/circuit.VALUES` (provenance in the `dk/circuit.py` docstring) |
| topology | `run_refs.ELEMENTS` (the same as `circuit.netlist()`) |
| solver: reltol 1e-6, abstol 1e-14, vntol 1e-9, chgtol 1e-16, 0.5 µs step and max step, trap | `run_refs.SOLVER` (#5) |
| `ngbehavior=psa` | `run_refs.NGBEHAVIOR`, checked against `.spiceinit` |
| analyses: `main` (.op, .ac 50/decade plus the exact 20 Hz and 20 kHz band edges, 1 kHz sines at 0.05/0.5/2/8 V for 500 ms), `burst` (4 V, 10-30 ms, 120 ms) | `run_refs.AC_GRID`, `AC_EDGES_HZ`, `SINE`, `AMPS`, `BURST` |

Models `koren` (`models/12ax7_koren.lib`) and `dz` (`models_dz/dz_12ax7.inc`) differ only in the valve line.
`stage_12ax7.cir` is the one committed netlist, the koren `main` netlist, marked GENERATED. Do not edit it:
change `VALUES`/`SOLVER` and run `python spice/run_refs.py --write-netlist`. To run it by hand:
`mkdir -p out && ../.ngenv/bin/ngspice -b stage_12ax7.cir`.
`tests/test_netlists.py` (no ngspice needed, runs in CI) parses the generated netlists. It fails if any value,
node, option or tran step diverges from `VALUES`/`SOLVER`, if `stage_12ax7.cir` is stale, or if the committed
JSONs were made with other settings. The hand-written `stage_12ax7_burst.cir` and `stage_12ax7_sine_long.cir`,
the 60 ms sine runs and the v2 `reference_sine.json`/`analyse_sine_long.py` were removed in #4 (see `RESULTS.md`).

## Test references
`reference_dz.json` and `reference_koren.json` need the lab Python env and the Koren model:
```bash
NGSPICE=../.ngenv/bin/ngspice python run_refs.py      # default NGSPICE is ../.ngenv/bin/ngspice; ~1 min/model
```
Each JSON records the solver settings, `.spiceinit` and the ngspice version under `"generator"`.
